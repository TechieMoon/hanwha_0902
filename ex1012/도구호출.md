# LLM에 도구(Function) 연결하기

LLM은 학습 이후의 정보(지금 시각, 오늘 날씨)를 모르고, 정확한 계산이나 실제 행동(메일 보내기, DB 쓰기)도 혼자서는 못 한다. 그래서 **도구(tool)**를 붙인다. 수업 자료의 표현대로 LLM은 "언어로 생각하는 두뇌"이고 도구는 "세상과 연결되는 손과 눈"이다. 이번 시간에는 OpenAI Responses API로 직접 만든 파이썬 함수를 도구로 연결하고, 도구를 호출하고 결과를 돌려주는 **에이전트 루프**를 만들었다.

- 코드: [`exam2.ipynb`](exam2.ipynb) (실습한 날씨 에이전트까지만 정리. Tool Schema 작성 원칙, 빌트인 툴, MCP 툴은 다음 수업에서 이어짐)

## 1. 도구가 없으면

```python
response = client.responses.create(model="gpt-4o-mini", input="지금 몇 시야? 그리고 오늘 날짜도 알려줘.")
```

```txt
지금 몇 시인지와 오늘 날짜는 제가 확인할 수 없어요. 하지만 당신의 기기에서 시계나 달력을 확인하면 정확한 시간을 알 수 있을 거예요. ...
```

날씨를 물어도 "현재 서울의 날씨 정보를 제공할 수는 없지만…"이라고 답했다.

## 2. 도구 만들기: 함수 + 명세(JSON Schema)

도구는 두 부분으로 이뤄진다.

1. **실제로 실행될 파이썬 함수**: 결과는 JSON 문자열로 돌려준다.
2. **모델에게 보여줄 명세**: 이름, 설명, 인자 형식을 JSON Schema로 적는다. 모델은 코드를 보지 못하고 이 명세만 보고 도구를 쓸지 판단한다.

```python
def get_current_time() -> str:
    now = datetime.datetime.now()
    return json.dumps({"current_time": now.strftime("%Y-%m-%d %H:%M:%S")})

available_tools = {"get_current_time": get_current_time}   # 이름 -> 실제 함수

tools_specification = [{
    "type": "function",
    "name": "get_current_time",
    "description": "사용자가 현재 시간, 오늘 날짜, 지금 시각 등을 물어볼 때 실시간 시스템 정보를 가져옵니다.",
    "parameters": {"type": "object", "properties": {}},     # 인자 없음
}]
```

## 3. 에이전트 루프

```python
input_history = [{"role": "user", "content": "지금 몇 시야? 그리고 오늘 날짜도 알려줘."}]

while True:
    response = client.responses.create(model="gpt-4o-mini", instructions="...", input=input_history, tools=tools_specification)
    input_history += response.output              # 모델의 응답(도구 요청 포함)을 기록에 추가

    has_tool_call = False
    for item in response.output:
        if item.type == "function_call":          # 모델이 도구 실행을 요청했으면
            has_tool_call = True
            tool_result = available_tools[item.name]()          # 내 코드가 실제로 실행
            input_history.append({"type": "function_call_output",  # 결과를 같은 call_id로 기록에 추가
                                  "call_id": item.call_id, "output": tool_result})

    if not has_tool_call:                         # 더 이상 요청이 없으면 최종 답변
        print(response.output_text)
        break
```

실행 결과 (`response.output` 출력은 줄였다):

```txt
[AI 요청]: 툴 'get_current_time' 실행이 필요합니다. (Call ID: call_IWvPmEfY9vRn3Ei6xmjwSrEb)
[툴 실행 결과]: {"current_time": "2026-10-12 16:20:53"}
[AI 요청]: 툴 'get_current_time' 실행이 필요합니다. (Call ID: call_tnACkFA6umFXDeQYwnexdvoo)
[툴 실행 결과]: {"current_time": "2026-10-12 16:20:53"}

--- AI Agent Loop 종료 ---

최종 AI 답변:
현재 시간은 16:20:53입니다. 오늘 날짜는 2026년 10월 12일입니다.
```

질문에 "몇 시"와 "날짜" 두 가지가 있어서, 모델이 첫 응답 하나에 `get_current_time` 호출을 **두 개** 담았다. 한 응답에 도구 요청이 여러 개 올 수 있기 때문에 `for item in response.output`으로 하나씩 처리한다. 결과마다 요청과 같은 `call_id`를 붙여야 모델이 어떤 요청의 결과인지 맞출 수 있다. 두 번째 응답에서는 도구 요청 없이 답만 와서 루프가 끝났다.

**역할 나누기가 핵심이다.** LLM은 "이 함수를 이 값으로 실행해라"라고 **결정**만 하고, 실제 **실행**은 내 파이썬 코드가 한다.

```txt
1단계  개발자 → LLM      : 질문 + 도구 명세(메뉴판) 전달
2단계  LLM → 애플리케이션 : "get_current_weather를 location='Seoul'로 실행해 줘" (function_call)
3단계  애플리케이션        : 실제 파이썬 함수 실행
4단계  애플리케이션 → LLM : 실행 결과 전달 → LLM이 사람이 읽을 답변 작성
```

## 4. 인자가 있는 도구: 실시간 날씨 에이전트

무료 날씨 서비스 `wttr.in`(`https://wttr.in/{도시}?format=j1`)에서 기온·날씨·습도를 가져오는 함수를 도구로 만들었다. 이번에는 **인자(location)**가 있어서, 명세의 `properties`에 인자 설명을 적고 `required`로 필수 인자임을 표시한다.

```python
"parameters": {
    "type": "object",
    "properties": {
        "location": {"type": "string", "description": "날씨를 조회할 영문 도시명 (예: 'Seoul', 'Tokyo', 'London', 'New York')"}
    },
    "required": ["location"],
}
```

루프에서는 모델이 정한 인자를 `json.loads(item.arguments)`로 꺼내서 `tool_func(**tool_args)`처럼 키워드 인자로 풀어 넣는다.

```txt
💬 사용자 질문: 지금 서울 날씨 어때? 그리고 런던 날씨도 같이 확인해줘.

🤖 Agent Loop 가동 시작...
👉 [AI 요청]: 툴 'get_current_weather' 실행 필요 (매개변수: {'location': 'Seoul'})
   [실행 완료]: 실시간 데이터 가져옴 -> {"location": "Seoul", "temperature_celsius": "27°C", "condition": "Patchy rain nearby", "humidity": "48%"}
👉 [AI 요청]: 툴 'get_current_weather' 실행 필요 (매개변수: {'location': 'London'})
   [실행 완료]: 실시간 데이터 가져옴 -> {"location": "London", "temperature_celsius": "14°C", "condition": "Overcast ", "humidity": "73%"}

🤖 Agent Loop 종료.

✨ 최종 AI 답변:
현재 서울의 날씨는 다음과 같습니다:
- **온도**: 27°C
- **상태**: 이곳 근처에서 가끔 비가 내리고 있습니다.
- **습도**: 48%

런던의 날씨는 다음과 같습니다:
- **온도**: 14°C
- **상태**: 흐림
- **습도**: 73%

두 도시 모두 기온과 습도가 많이 다르니 참고하세요!
```

확인한 점:

- **한국어 질문에서 영어 인자를 뽑았다.** "서울", "런던"이라고 물었지만 명세에 "영문 도시명"이라고 적어 둔 대로 `Seoul`, `London`으로 바꿔서 넘겼다. 도구 설명이 곧 모델에게 주는 사용 설명서다.
- **두 도시를 한 번에 요청했다.** 시간 예제처럼 한 응답에 도구 호출 두 개가 들어왔다.
- **날씨 설명은 영어로 왔다.** 코드는 응답에 `lang_ko` 필드가 있으면 한국어 설명을 쓰도록 되어 있지만, 요청 URL에 언어 옵션이 없어서 영어 설명(`Patchy rain nearby`, `Overcast`)이 쓰였다. 최종 답변에서는 모델이 이걸 한국어로 옮겼다.
- 이 셀은 앞 셀(시간 도구)에서 import한 `json`을 그대로 쓴다. 셀을 따로 실행하려면 `import json`이 필요하다.

## 정리

| 개념 | 코드 | 핵심 |
|---|---|---|
| 도구 = 함수 + 명세 | 파이썬 함수 + `{"type": "function", "name", "description", "parameters"}` | 모델은 명세(설명·인자 형식)만 보고 판단한다 |
| 도구 연결 | `client.responses.create(..., tools=tools_specification)` | 필요하면 응답에 `function_call`이 담겨 온다 |
| 실행 | `available_tools[item.name](**json.loads(item.arguments))` | LLM은 결정, 실행은 내 코드 |
| 결과 전달 | `{"type": "function_call_output", "call_id": ..., "output": ...}` | 같은 `call_id`로 대화 기록에 추가해 다시 호출 |
| 에이전트 루프 | `while True` + `function_call`이 없으면 `break` | 도구가 더 필요 없을 때까지 요청 → 실행 → 전달 반복 |
| 병렬 호출 | `for item in response.output` | 한 응답에 도구 요청이 여러 개 올 수 있다 |
