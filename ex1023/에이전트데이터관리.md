# 에이전트 데이터 관리: State · Reducer · Messages · Context · Checkpointer · Store · Tool

> **한눈에 보기**
> - 에이전트의 데이터는 **통로가 여러 개**다. 헷갈리지 않게 구분하는 것이 이날의 목표
> - **State** = 실행 중 노드들이 함께 읽고 쓰는 작업 공간 / **Reducer** = 업데이트를 합치는 규칙 / **MessagesState** = 대화 메시지 전용 State
> - **Runtime Context** = 실행마다 넣어 주는 읽기 전용 설정(State에 저장 안 됨) / **Checkpointer** = `thread_id`별 State 스냅샷(단기 기억) / **Store** = 대화방을 넘어 공유하는 장기 기억
> - **State와 Context는 그 자체로 DB가 아니다.** 저장은 Checkpointer·Store가 하고, `InMemory*`는 커널을 끄면 사라진다
> - Store에 저장했다고 LLM이 알아서 읽지 않는다. **코드(노드·도구)가 꺼내서** 모델에 넣어 줘야 한다

- 코드: [`exam11.ipynb`](exam11.ipynb) (강사님 자료 `fwedu/exam11.ipynb` 사본, 강의 슬라이드 이미지 포함(설명 예시 속 사람 이름만 가림), 📝 정리 셀 추가)
- 1~10장은 LLM 없이, 11장만 `gpt-4o-mini`로 실행. 같은 날 배운 [LangGraph 기본](LangGraph기본.md) · [흐름 제어](LangGraph흐름제어.md) · [에이전트와 운영](LangGraph에이전트와운영.md)을 "데이터가 어디에 있나" 관점으로 다시 묶은 노트북이다.

## 데이터 통로 한 장 정리

| 통로 | 무엇 | 수명 | 저장 위치 | 코드 |
|---|---|---|---|---|
| State | 노드들이 공유하는 작업 데이터 | 한 번의 실행(체크포인터가 있으면 thread 동안) | 메모리 | `StateGraph(State)`, 노드가 dict 반환 |
| Reducer | 업데이트 병합 규칙 | - | - | `Annotated[list, operator.add]` |
| Messages | Human/AI/Tool 메시지 | State와 같음 | State의 `messages` | `MessagesState`(`add_messages`) |
| Input/Output Schema | 밖에서 넣고 받는 모양 | - | - | `input_schema=`, `output_schema=` |
| Runtime Context | 사용자 ID·언어·모델 버전 같은 설정 | 이번 실행만 | 저장 안 함 | `context_schema=`, `runtime.context` |
| Checkpointer | thread별 State 스냅샷 이력 | thread 동안 | `InMemorySaver` / `PostgresSaver` | `compile(checkpointer=)`, `thread_id` |
| Store | 사용자 프로필 같은 장기 기억 | 대화방을 넘어 | `InMemoryStore` / `PostgresStore` | `compile(store=)`, `runtime.store` |
| Streaming | 실행 중 실시간 전달 | 전달하고 끝 | 저장 안 함 | `stream(stream_mode=...)` |

## 1~4장. State, Reducer, MessagesState, 입출력 스키마

- **State**: `classify`가 `category`만 반환해도 `question`은 그대로 남고, 다음 노드 `write_answer`가 `category`를 읽었다. `add_edge()`는 **실행 순서**를 잇는 것이지 데이터를 복사해 넘기는 API가 아니다. 데이터는 공유 State를 통해 전달된다.
- **Reducer**: `steps: Annotated[list[str], operator.add]`는 `['A 완료', 'B 완료']`로 쌓이고, 리듀서 없는 `status`는 마지막 값 `'B'`.
- **MessagesState 상속**: `class State3(MessagesState): summary: str`처럼 메시지 외 필드를 더할 수 있다. `stream_mode="debug"`로 보니 `task`(입력) → `task_result`(결과) 이벤트가 타임스탬프와 함께 나왔다.
- **입출력 스키마**: 내부 필드 `search_result`는 숨기고 `{'answer': 'State란? → State를 노드가 공유합니다.'}`만 반환. 공개 API 계약과 내부 작업 데이터를 분리한다.

## 5장. Runtime Context

```python
def answer5(state, runtime: Runtime[Context5]):
    ctx = runtime.context            # {"user_id": "u01", "language": "한국어"}
graph5.invoke({...}, context={"user_id": "u01", "language": "한국어"})
# → '[u01] 한국어로 답변: 안녕하세요'
```

예전 방식인 `config={"configurable": {"user_id": ..., "model_version": ...}}`를 노드의 `config: RunnableConfig` 인자로 읽는 예제도 같이 봤다. `configurable`에는 `thread_id`도 들어간다. Context는 "지금 누구의 기억을 꺼낼지 알려 주는 열쇠(ID)", 장기 기억은 그 열쇠로 여는 저장소라는 비유가 나왔다.

## 6~7장. Command와 Send

- `Command(update={"route": route}, goto=route)`: 85점 → pass_node "합격", 40점 → retry_node "재학습 필요". 노드 안 로직으로 바로 다음 경로를 정할 때, 멀티 에이전트의 **핸드오프**("이건 재무 담당에게"), `interrupt()`와 결합한 승인에 쓴다.
- `Send("worker", {"item": x})`: 워커마다 **자기 전용 State(`WorkerState`)**를 받는다. `[2, 3, 4]` → `[4, 9, 16]`, `[1..5]` × 10 → `[10, 20, 30, 40, 50]`. 결과는 `operator.add` 리듀서로 충돌 없이 합쳐졌다.

## 8장. Checkpointer: thread별 단기 기억과 이력

| | session-A (2번 호출) | session-B (1번 호출) |
|---|---|---|
| `count` | 2 | 1 |
| 메시지 | Human, AI, Human, AI | Human, AI |
| 체크포인트 수 | **6** | **3** |

체크포인터는 메시지만이 아니라 **State 전체(`count`까지)의 스냅샷**을 슈퍼스텝마다 저장한다(호출 1번 = 입력·노드 실행 전·후 3개). `get_state()`는 특정 시점 하나, `get_state_history()`는 최신 → 과거 이력으로 디버깅·되돌리기(Time Travel)에 쓴다.

## 9장. Store: 대화를 넘는 장기 기억

```python
def load_profile9(state, runtime: Runtime[Context9]):
    item = runtime.store.get(("users", runtime.context["user_id"]), "profile")
    return {"preference": item.value["preferred_language"] if item else "미설정"}
graph9 = b.compile(store=store9, checkpointer=InMemorySaver())
```

- Context(누구) → Store(그 사람의 기억) → State(이번 실행에 기록) → 다음 노드가 사용. 세 통로가 어떻게 이어지는지 보여 주는 예제다.
- 첫 실행이 **"미설정 예제로 …"**가 나왔다. 앞 셀에서 u01 프로필을 넣은 `store9`를 이 셀에서 `InMemoryStore()`로 **새로 만들어 버렸기** 때문이다. InMemory 저장소는 객체를 새로 만들면 비어 있다. `("users", "unico")`에 "파이썬"을 넣은 뒤에는 "파이썬 예제로 …"라고 답했다.
- Store에 넣는다고 LLM이 자동으로 읽지 않는다. 이 예제처럼 **노드나 도구가 꺼내서** 넘겨야 한다.

## 10장. Streaming ≠ 저장

`stream(stream_mode="updates")`는 노드별 업데이트를 **실시간으로 전달**할 뿐이고, 저장은 체크포인터가 한다. 둘을 혼동하지 않는다.

## 11~12장. 실제 에이전트와 ToolRuntime

- `create_agent(model, tools=[double_number], system_prompt=..., checkpointer=InMemorySaver())`: "37의 두 배" → Tool 74 → "74입니다", 이어서 "방금 계산한 내용이 뭐였지?" → 같은 thread라 기억했다. 저장된 State 필드는 `['messages']`뿐 — **system_prompt는 State에 저장되지 않는다.**
- 도구가 공유 State까지 바꾸려면 `ToolRuntime` + `Command(update={"search_result": ..., "messages": [ToolMessage(..., tool_call_id=runtime.tool_call_id)]})`를 반환한다. 실제로 쓰려면 그 필드를 가진 커스텀 State가 필요해서 이날은 코드만 읽었다.

## 13장. 실서비스로 확장할 때

| 기능 | 대표 구성 |
|---|---|
| 영속 단기·장기 기억 | `PostgresSaver`, `PostgresStore` (10/21에 실습) |
| RAG | PGVector 등 Vector Store + Retriever (10/20에 실습) |
| 서브그래프 / 사람 승인 | `add_node("sub", compiled)`, `interrupt()` + `Command(resume=)` |
| 상태 복구·분기 | `get_state_history()`, checkpoint config |
| 출력 형식 / 긴 대화 | `response_format`, `with_structured_output()` / trim·summarize 미들웨어 |
| 실행 추적 | LangSmith |

Vector Store는 **검색할 자료**를, LangGraph Store는 **에이전트의 기억·사용자 정보**를 저장한다는 점도 구분한다.

## 🔁 복습 질문

<details>
<summary>1. <code>add_edge("A", "B")</code>는 A의 결과를 B에게 어떻게 전달하나?</summary>

직접 전달하지 않는다. 실행 순서만 정하고, A가 반환한 값이 공유 State에 반영되면 B가 State에서 읽는다.
</details>

<details>
<summary>2. Runtime Context와 State의 차이는?</summary>

Context는 실행마다 넣어 주는 읽기 전용 설정이라 체크포인트에 저장되지 않고, State는 노드가 읽고 쓰며 체크포인터가 저장한다.
</details>

<details>
<summary>3. 체크포인터는 무엇을 저장하나?</summary>

메시지만이 아니라 State 전체의 스냅샷을 thread별로, 슈퍼스텝마다 저장한다.
</details>

<details>
<summary>4. Store에 사용자 프로필을 넣으면 LLM이 알아서 그 내용을 쓰나?</summary>

아니다. 노드나 도구가 `store.get/search`로 꺼내서 프롬프트나 State에 넣어 줘야 한다.
</details>

<details>
<summary>5. 9장 첫 실행이 "미설정"으로 나온 이유는?</summary>

같은 이름의 `store9`를 `InMemoryStore()`로 새로 만들어서 앞에서 넣은 데이터가 없는 저장소를 썼기 때문이다.
</details>

<details>
<summary>6. <code>create_agent</code>의 system_prompt는 체크포인트에 저장되나?</summary>

아니다. 저장된 State 필드는 `messages`뿐이었다. 시스템 프롬프트는 모델을 호출할 때마다 붙는 설정이다.
</details>
