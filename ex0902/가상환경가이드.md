# 가상환경(venv)

> **한눈에 보기**
> - 가상환경은 **프로젝트마다 따로 쓰는 파이썬 + 라이브러리 공간**이다. 프로젝트끼리 라이브러리 버전이 섞이지 않는다.
> - 만들기 `python -m venv 폴더이름` → 켜기 `폴더이름\Scripts\activate` → 끄기 `deactivate`
> - 켜진 상태에서 `pip install`한 라이브러리는 그 가상환경 안에만 설치된다.

## 파이썬 버전 확인하기

VS Code에서 터미널 여는 법: ``Ctrl + ` ``

```cmd
python --version
```

```txt
Python 3.12.10
```

## 가상환경 만들기

```cmd
python -m venv .firstvenv
```

현재 폴더 안에 `.firstvenv` 폴더가 생기고, 그 안에 이 프로젝트 전용 파이썬과 `pip`가 들어간다.

## 가상환경 켜기

```cmd
.firstvenv\Scripts\activate.bat
```

가상환경이 생성된 폴더의 `Scripts\activate.bat`의 상대 경로를 복사해서 cmd에서 실행한다. 켜지면 프롬프트 앞에 가상환경 이름이 붙는다.

```txt
(.firstvenv) C:\Users\start\Documents\GitHub\hanwha_0902>
```

- PowerShell 터미널이라면 `.firstvenv\Scripts\Activate.ps1`을 실행한다.
- VS Code에서 인터프리터를 이 가상환경으로 골라 두면, 새 터미널을 열 때 자동으로 켜진다.

## 가상환경 끄기

```cmd
deactivate
```

(`.firstvenv\Scripts\deactivate.bat`처럼 경로를 적어도 된다.)

## 기억할 것

- 가상환경 폴더는 컴퓨터마다 다시 만들 수 있으므로 **깃허브에 올리지 않는다.** `.gitignore`에 `.venv/`, `.firstvenv/`처럼 적어 둔다.
- 다른 컴퓨터에서 같은 환경을 만들려면 `pip freeze > requirements.txt`로 목록을 저장하고, `pip install -r requirements.txt`로 설치한다.

## 복습 질문

<details>
<summary>1. 가상환경을 쓰는 이유는?</summary>

프로젝트마다 필요한 라이브러리와 버전이 다르기 때문이다. 하나의 파이썬에 다 설치하면 버전이 충돌할 수 있다.
</details>

<details>
<summary>2. 가상환경이 켜졌는지 어떻게 알 수 있나?</summary>

프롬프트 앞에 <code>(.firstvenv)</code>처럼 가상환경 이름이 붙는다.
</details>

<details>
<summary>3. 가상환경 폴더를 깃허브에 올리지 않는 이유는?</summary>

용량이 크고 컴퓨터(운영체제)마다 내용이 달라서 그대로 옮겨 쓸 수 없다. 대신 <code>requirements.txt</code>로 라이브러리 목록만 공유한다.
</details>
