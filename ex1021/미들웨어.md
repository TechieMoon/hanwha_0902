# LangChain 미들웨어: 훅 6가지와 내장 미들웨어 9종

> **한눈에 보기**
> - 미들웨어 = 에이전트 루프(모델 → 도구 → 모델 …)의 **정해진 지점(훅)에 끼우는 부품**. 에이전트 코드를 고치지 않고 로그·요약·승인·재시도·제한·개인정보 보호를 붙인다
> - 훅 6가지: `before_agent` / `before_model` / `wrap_model_call` / `after_model` / `wrap_tool_call` / `after_agent`. `before/after`는 길목, `wrap`은 `handler(request)`를 감싸는 껍질
> - `middleware=[A, B]` = 양파 껍질: before는 A→B, wrap은 A가 바깥, **after는 B→A(역순)**
> - 내장: 요약, 사람 승인(HITL), 호출 횟수 제한, 재시도, 대체 모델, 개인정보 가리기(PII), 할 일 목록
> - 실패·무한 루프는 진짜 모델로 재현하기 어려워 **일부러 실패하는 가짜 모델**(`FlakyModel`, `ScriptedModel`)로 확인했다

- 코드: [`exam7.ipynb`](exam7.ipynb) (강사님 자료 `fwedu/exam7.ipynb` 사본, 강의 슬라이드 이미지 포함, 📝 정리 셀 추가)
- 실행 환경: langchain 1.4.6, langchain-openai 1.7.2, langgraph 1.2.x, `gpt-4o-mini`
- 10/08에 책으로 배운 [create_agent 미들웨어](../ex1008/create_agent미들웨어.md)를 9종 전부로 넓혔다.

## 훅의 실행 순서 (노트북 1~2장, 직접 만든 미들웨어)

6가지 훅에 기록만 남기는 미들웨어를 꽂고 "서울 날씨 알려줘"를 실행한 결과:

```
① before_agent    — 에이전트 시작 (1번)
② before_model    — 모델 호출 직전 (메시지 1개)
③ wrap_model_call — 감싸기 시작 → 끝 (1.29초)
④ after_model     — 모델 응답 직후 (도구 호출 요청)
⑤ wrap_tool_call  — 도구 'get_weather' 실행, 인자={'city': '서울'}
② before_model    — (메시지 3개)
③ wrap_model_call — (0.95초)
④ after_model     — (최종 답변)
⑥ after_agent     — 에이전트 종료 (1번)
```

- ①⑥은 한 번, ②③④는 **모델을 부를 때마다**, ⑤는 도구를 실행할 때만.
- `before_*`/`after_*`는 `(state, runtime)`을 받고 `None`을 돌려주면 "안 바꿈". `wrap_*`는 `(request, handler)`를 받고 **`handler(request)`를 불러야 진짜 호출**이 된다.
- 여러 개를 꽂으면: `A.before → B.before → A.wrap 시작 → B.wrap 시작 → (모델) → B.wrap 끝 → A.wrap 끝 → B.after → A.after`. 그래서 PII 가리기는 **맨 바깥**(원문이 아무 데도 안 가게), 재시도는 **모델 가까운 안쪽**에 둔다.

### 직접 만든 미들웨어 예

| 미들웨어 | 훅 | 결과 |
|---|---|---|
| `@dynamic_prompt` 사용자 이름·권한별 시스템 프롬프트 | wrap_model_call 간편형 | "안녕하세요, 둘리님!"(일반 → 쉬운 말), "도우너님!"(관리자) |
| 대화 길이로 모델 바꾸기 `request.override(model=...)` | wrap_model_call | 메시지 1·3개는 `gpt-4o-mini`, 5개부터 `gpt-4o` |
| 금지어 차단 `@before_model(can_jump_to=["end"])` | before_model | "비밀번호" 질문은 **LLM을 부르지 않고** "보안 정책에 따라 처리할 수 없는 요청입니다"로 종료 |
| LLM 호출 시간 측정 (`try/finally`) | wrap_model_call | 3.63초, 3.44초 … 오류가 나도 시간은 찍힌다 |

> 금지어 실습에서 통과한 질문 "RAG의 장점을 한 문장으로"에 모델이 RAG를 **"Recall-Augmented Generation"**이라고 답했다. 맞는 이름은 Retrieval-Augmented Generation이다. 10/19 "LCEL"처럼, 근거 없이 약자를 물으면 지어낸다.

## 내장 미들웨어 (노트북 3~9장)

### 3. SummarizationMiddleware: 긴 대화 자동 요약

```python
SummarizationMiddleware(model=model, trigger=("messages", 6), keep=("messages", 2))   # + checkpointer
```

- 저장된 메시지 수: 2 → 4 → 6 → **4** → 6 → **4**. 6개를 넘으면 오래된 메시지를 요약 1개로 바꾸고 최근 2개만 원문으로 남겼다. 도구 요청과 결과는 한쪽만 잘리지 않게 경계를 조정한다.
- 요약 뒤에도 "제 이름과 취미, 강아지 이름?" → "둘리, **하이킹**, 또치". **"등산"이 "하이킹"으로 바뀌었다.** 기본 요약 프롬프트가 영어라 요약문이 영어로 만들어지면서("enjoys hiking") 원래 단어가 번역돼 버린 것이다. 한국어 서비스라면 `summary_prompt=`에 "한국어로, 고유명사·원래 단어를 그대로" 같은 지시를 넣은 프롬프트를 주는 것이 좋다(`{messages}` 자리 포함).
- 요약문은 `HumanMessage`로 들어가고 `additional_kwargs={'lc_source': 'summarization'}` 표시가 붙는다.

### 4. HumanInTheLoopMiddleware: 위험한 도구는 사람이 승인

```python
HumanInTheLoopMiddleware(interrupt_on={"send_email": True})     # checkpointer 필수
result["__interrupt__"][0].value["action_requests"]               # 멈춘 이유: 도구와 인자
agent.invoke(Command(resume={"decisions": [{"type": "approve"}]}), cfg)   # 같은 thread_id로 재개
```

| 결정 | 결과 |
|---|---|
| approve | 그대로 발송 |
| reject + 메시지 | "현재 외부 메일 발송이 금지되어 있습니다" — 거부 사유가 모델에게 전달됨 |
| edit + `edited_action` | 받는 사람을 manager@example.com으로 바꿔서 발송 |

`get_weather`처럼 지정하지 않은 도구는 바로 실행된다. 실제 서비스에서는 `__interrupt__`를 화면에 보여 주고 버튼으로 `Command(resume=...)`를 보낸다. `{"allowed_decisions": ["approve", "reject"]}`로 고를 수 있는 결정을 제한할 수도 있다.

### 5. 호출 횟수 제한

| 설정 | 결과 (계속 도구만 부르는 가짜 모델) |
|---|---|
| `ModelCallLimitMiddleware(run_limit=3, exit_behavior="end")` | 모델 3번·도구 3번 후 "Model call limits exceeded: run limit (3/3)"로 종료 |
| `ToolCallLimitMiddleware(tool_name=..., run_limit=2)` | 도구 실제 실행 2번, 3번째 요청은 차단 "(3/2 calls)" |
| `exit_behavior="error"` | `ModelCallLimitExceededError` 예외 (운영 알람 연동용) |

`run_limit`은 `invoke` 한 번 기준, `thread_limit`은 같은 thread 전체 기준(checkpointer 필요). 10/08에 겪은 `GraphRecursionError`([RAG 에이전트](../ex1008/RAG에이전트그래프.md))를 미들웨어로 미리 막는 방법이다.

### 6. 재시도와 7. 대체 모델

| 실험 | 결과 |
|---|---|
| 재시도 없음 + 처음 2번 실패하는 모델 | 첫 실패에서 바로 예외 |
| `ModelRetryMiddleware(max_retries=2)` | 3번째 호출에서 성공 |
| 99번 실패, `on_failure="continue"` | 3번 시도 후 "Model call failed after 3 attempts …"를 메시지로 남기고 종료 |
| `ToolRetryMiddleware` + 2번 타임아웃 나는 도구 | 도구 3번 실행해서 "연필: 12,000원" |
| `ModelFallbackMiddleware(backup1, backup2)` | 1순위·2순위 실패 → 3순위가 답함 (각 1번씩 시도) |

`max_retries`는 첫 시도 **이후** 추가 횟수, 대기는 지수 백오프(1→2→4초, `jitter`로 흔들기). 보통 "같은 모델 재시도(안쪽) → 다른 모델 전환(바깥)" 순서로 조합한다. 잘못된 인자 같은 영구 오류는 `retry_on=`으로 재시도 대상에서 뺀다.

### 8. PIIMiddleware: 모델에 보내기 전에 개인정보 가리기

| 유형 | strategy | 모델이 받은 값 |
|---|---|---|
| email | redact | `[REDACTED_EMAIL]` |
| credit_card | mask | `**** **** **** 1111` |
| 한국 휴대폰(정규식 `detector`) | hash | `<kr_phone_hash:e07c05a8>` |
| API 키 `sk-...` | block | `PIIDetectionError` 예외로 입력 자체를 거부 |

기본은 **사용자 입력만** 검사한다. 모델 출력·도구 결과도 검사하려면 `apply_to_output=True`, `apply_to_tool_results=True`.

### 9. TodoListMiddleware: 할 일 목록으로 계획

`write_todos` 도구와 사용 지침을 자동으로 넣어 준다. "서울·부산 여행 계획(날씨 확인 → 옷차림 → 요약)" 요청에 할 일 3개가 모두 `completed`가 됐고 결과는 상태의 `todos`에 남았다. 체크리스트 UI로 진행 상황을 보여 줄 때 쓴다.

## 실무 조합과 응용 (노트북 10장)

```python
middleware=[
    PIIMiddleware("email", strategy="redact"),                     # 가장 바깥: 원문이 어디에도 안 가게
    SummarizationMiddleware(model=model, trigger=("tokens", 3000), keep=("messages", 10)),
    ModelCallLimitMiddleware(run_limit=10, exit_behavior="end"),
    ToolCallLimitMiddleware(run_limit=5, exit_behavior="end"),
    ModelFallbackMiddleware(ChatOpenAI(model="gpt-4o")),
    ModelRetryMiddleware(max_retries=2),                            # 모델에 가장 가까이
    HumanInTheLoopMiddleware(interrupt_on={"send_email": True}),
]
```

**응용 1. 배송 상담 에이전트** (`ToolRetryMiddleware` + 도구·모델 호출 제한): ORD-1002 조회가 처음에 "배송 서버 일시 장애"로 실패했지만 재시도로 2회째에 성공해 "10월 23일 도착"이라고 답했다. 없는 주문 ORD-9999는 "존재하지 않습니다".

**응용 2. 쇼핑 주문 에이전트** (HITL로 `place_order`만 승인, 가격 조회는 자동): 기계식 키보드 2개 주문 → 승인 요청에서 멈춤 → `y` 입력 → 178,000원 주문 확정. `invoke(..., version="v2")`를 쓰면 결과가 `result.interrupts`, `result.value["messages"]`처럼 나뉘어 나온다.

## 정리

| 이런 문제 | 미들웨어 |
|---|---|
| 대화가 길어져 비용·한도 문제 | `SummarizationMiddleware` |
| 위험한 도구를 마음대로 실행할까 걱정 | `HumanInTheLoopMiddleware` |
| 무한 반복, 비용 폭주 | `ModelCallLimitMiddleware`, `ToolCallLimitMiddleware` |
| API가 가끔 실패 | `ModelRetryMiddleware`, `ToolRetryMiddleware` |
| 모델·제공자 장애 | `ModelFallbackMiddleware` |
| 개인정보가 모델·로그로 샘 | `PIIMiddleware` |
| 복잡한 다단계 작업 | `TodoListMiddleware` |
| 나만의 규칙 | `@before_model`, `@wrap_model_call`, `@wrap_tool_call` 등 직접 작성 |

**에이전트 본체는 그대로 두고, 필요한 기능은 미들웨어로 꽂는다.** 순서는 `middleware=[바깥, …, 안쪽]`.

## 🔁 복습 질문

<details>
<summary>1. <code>wrap_model_call</code> 함수 안에서 <code>handler(request)</code>를 부르지 않으면?</summary>

진짜 모델이 호출되지 않는다. 금지어 차단처럼 일부러 막을 때가 아니면 반드시 불러서 그 결과를 돌려줘야 한다.
</details>

<details>
<summary>2. <code>middleware=[A, B]</code>일 때 <code>after_model</code>의 실행 순서는?</summary>

B → A (역순). before는 목록 순서, wrap은 A가 바깥에서 B를 감싼다.
</details>

<details>
<summary>3. PIIMiddleware를 목록 맨 앞에 두는 이유는?</summary>

가장 바깥에서 먼저 가려야 뒤의 미들웨어(요약, 로깅 등)와 모델에 원문이 전달되지 않기 때문이다.
</details>

<details>
<summary>4. 요약 미들웨어를 쓴 뒤 "등산"이 "하이킹"으로 바뀐 이유와 대책은?</summary>

기본 요약 프롬프트가 영어라 요약문이 영어로 만들어지며 단어가 번역됐다. `summary_prompt`에 한국어로, 원래 단어를 유지하라는 지시를 넣는다.
</details>

<details>
<summary>5. HumanInTheLoopMiddleware에 checkpointer가 꼭 필요한 이유는?</summary>

도구 실행 직전에 멈춘 상태를 저장해 두었다가, 같은 `thread_id`로 `Command(resume=...)`를 받으면 그 지점부터 이어서 실행해야 하기 때문이다.
</details>

<details>
<summary>6. 재시도와 대체 모델을 같이 쓸 때 순서는?</summary>

재시도를 모델에 가까운 안쪽에, 대체 모델을 바깥에 둔다. 같은 모델로 먼저 다시 해 보고, 그래도 안 되면 다른 모델로 넘어간다.
</details>
