# 요청 본문(Pydantic)과 값 검증, 오류 응답

> **한눈에 보기**
> - POST·PUT의 JSON 본문은 **pydantic 모델**로 받는다 (틀리면 422, `loc: body`)
> - `Query(min_length=, pattern=)`, `Annotated[int, Path(ge=1)]`로 파라미터에 조건
> - `raise HTTPException(404, detail=...)`로 직접 오류 응답, `status_code=201`로 성공 코드 지정
> - `response_model=`로 나가는 데이터의 형식도 검증 (모델에 없는 필드는 빠진다)

POST·PUT 요청으로 JSON 데이터를 받는 방법과, 들어오는 값과 나가는 값을 검증하는 방법을 실습했다. FastAPI는 **pydantic 모델**로 요청 본문의 형식을 정의하고, `Query()`·`Path()`로 파라미터에 조건을 붙이며, `response_model`로 응답 형식을 정한다. 조건에 맞지 않으면 함수가 실행되기 전에 422 오류가 자동으로 나간다.

- 코드: [`exam10.py`](exam10.py) ~ [`exam14.py`](exam14.py)
- POST·PUT은 브라우저 주소창으로 보낼 수 없어서 `/docs`의 **Try it out**으로 테스트한다.

## 1. 요청 본문 (exam10, exam11)

```python
class Item(BaseModel):
    name: str                       # 필수
    description: str | None = None # 선택
    price: float                    # 필수
    tax: float | None = None        # 선택

@app.post("/items", status_code=201)
async def create_item(item: Item):
    item_dict = item.model_dump()   # 모델 -> 딕셔너리
    ...
```

| 보낸 본문 | 결과 |
|---|---|
| `{"name":"둘리","price":10.5,"tax":1.5}` | **201** `{..., "method":"POST","price_with_tax":12.0}` |
| `{"name":"또치","price":10,"tax":0}` | **201** `price`가 `10.0`으로 변환, `price_with_tax` **없음** |
| `{"name":"x"}` | **422** `missing`: `loc: ["body","price"]` |

- `status_code=201`: 성공하면 200 대신 201 Created로 응답한다. 새 데이터를 만드는 POST에 맞는 상태 코드다.
- **`tax`가 0이면 세금 포함 가격이 빠진다.** `if item.tax:`는 0도 거짓으로 보기 때문이다. "값이 없을 때만" 거르려면 `if item.tax is not None:`으로 써야 한다.

**어디서 값을 찾는가 (exam11):** `PUT /items/5?q=hello` + 본문 `{"name":"둘리","price":3}` → `{"item_id":5,"name":"둘리","description":null,"price":3.0,"tax":null,"q":"hello"}`

| 인자 | 찾는 곳 |
|---|---|
| 경로의 `{item_id}`와 이름이 같음 | 경로 |
| pydantic 모델 타입 (`item: Item`) | 요청 본문(JSON) |
| 단순 타입 (`q: str`) | 쿼리 문자열 |

## 2. 쿼리·경로 파라미터 검증 (exam12, exam13)

```python
q: Union[str, None] = Query(default=None, min_length=3, max_length=10, pattern="^unico")
item_id: Annotated[int, Path(title="The ID of the item to get", ge=1)]
```

| 요청 | 결과 |
|---|---|
| `/items2/?q=abc` (5 ~ 50글자) | **422** `string_too_short` |
| `/items3/?q=unicorn` ("unico"로 시작, 3 ~ 10글자) | 통과 |
| `/items3/?q=hello` | **422** `string_pattern_mismatch` |
| `/items3/?q=unico12345678` | **422** `string_too_long` |
| `/items2/0` (1 이상) | **422** `greater_than_equal` |
| `/items2/5` | `{"item_id":5,"q":"unico"}` (q는 기본값) |

`Union[str, None]`은 `str | None`의 옛 표기다. `Annotated[타입, Path(...)]`는 타입과 검증 조건을 한 번에 적는 방식으로, `title` 같은 설명은 `/docs` 문서에 나온다.

## 3. 직접 오류 응답하기 (exam13)

```python
if item_id not in items:
    raise HTTPException(status_code=404, detail=f"{item_id} 명의 아이템은 존재하지 않습니다.")
```

`/items/dooly` → `{"item":"귀여운 아기 공룡"}`, `/items/ddochi` → **404** `{"detail":"ddochi 명의 아이템은 존재하지 않습니다."}`

422는 FastAPI가 형식 검사에서 자동으로 내는 오류이고, 404처럼 "형식은 맞지만 데이터가 없는" 경우는 `HTTPException`으로 직접 낸다.

## 4. 응답 모델 (exam14)

```python
@app.post("/items1", response_model=Item)
@app.get("/items2", response_model=list[Item])
@app.get("/items4", response_model=dict[str, float])
```

| 요청 | 결과 |
|---|---|
| POST `/items1` 본문 `{"name":"둘리","price":1,"secret":"x"}` | `{"name":"둘리","description":null,"price":1.0,"tax":null,"tags":[]}` |
| GET `/items2` (`{"name","price"}`만 있는 딕셔너리 3개 반환) | 3개 모두 `description`, `tax`, `tags`가 기본값으로 채워짐 |
| GET `/items4` | `{"foo":2.3,"bar":3.4}` |

- 모델에 없는 필드(`secret`)는 응답에서 빠졌다. `response_model`은 응답을 **검증하고 걸러 내는** 역할도 해서, 비밀번호처럼 내보내면 안 되는 필드를 막는 데 쓴다.
- 함수가 딕셔너리를 돌려줘도 모델 형식으로 바뀌어 빠진 필드가 기본값(`null`, `[]`)으로 채워진다.

## 정리

| 기능 | 코드 | 실패 시 |
|---|---|---|
| 요청 본문 | `item: Item` (pydantic `BaseModel`) | 422 (`loc: body`) |
| 성공 상태 코드 | `@app.post(..., status_code=201)` | |
| 쿼리 검증 | `Query(min_length=, max_length=, pattern=)` | 422 (`loc: query`) |
| 경로 검증 | `Annotated[int, Path(ge=1)]` | 422 (`loc: path`) |
| 직접 오류 | `raise HTTPException(status_code=404, detail=...)` | 404 + `detail` |
| 응답 형식 | `response_model=Item`, `list[Item]`, `dict[str, float]` | 모델에 없는 필드는 빠짐 |

어디서 받은 값이 틀렸는지다: 요청 본문, 쿼리 파라미터, 경로 파라미터.

<details>
<summary>2. <code>response_model</code>을 쓰면 좋은 점은?</summary>

응답 형식이 문서(/docs)에 나타나고, 비밀번호처럼 모델에 없는 필드가 실수로 나가는 것을 막는다.
</details>

<details>
<summary>3. <code>Path(ge=1)</code>은 무엇을 검사하나?</summary>

경로 값이 1 이상인지. 0이나 음수면 422.
</details>
