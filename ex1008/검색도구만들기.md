# 검색 도구 만들기 (create_retriever_tool)

> **한눈에 보기**
> - 저장해 둔 Chroma DB를 **같은 임베딩 모델·컬렉션 이름**으로 다시 불러온다 (경로가 틀리면 에러 없이 빈 DB)
> - `as_retriever(search_kwargs={"k": 3})` → `create_retriever_tool(retriever, name, description)`로 에이전트용 검색 도구
> - 도구 결과는 본문만 이어 붙인 문자열 → `document_prompt`로 쪽 번호를 함께 넣을 수 있다

6.5.2에서 PDF(한글 맞춤법·표준어 규정 해설)를 청크 510개로 나눠 Chroma 벡터 DB에 저장했다([벡터DB저장과검색.md](벡터DB저장과검색.md)). 이번에는 저장해 둔 DB를 다시 불러와 **retriever(검색기)**로 만들고, `create_retriever_tool`로 감싸서 **에이전트가 호출할 수 있는 검색 도구**를 만든다(교재 6.5.3). 다음 단계(6.5.4)에서 이 도구를 에이전트에 연결한다.

- 코드: [`rag_agent/retriever.py`](rag_agent/retriever.py)

```python
from langchain_chroma import Chroma 
from langchain_openai import OpenAIEmbeddings 
# create_retriever_tool: retriever(검색기)를 에이전트가 호출할 수 있는 도구로 감싸 주는 함수
from langchain_core.tools import create_retriever_tool

from dotenv import load_dotenv

# .env의 OPENAI_API_KEY를 불러온다. (검색어를 임베딩할 때 필요)
load_dotenv()

# 6.5.2 노트북이 만든 벡터 DB 폴더. 실행한 위치(ex1008 폴더) 기준 상대 경로라서, 다른 위치에서 실행하면
# 에러 없이 빈 DB가 새로 만들어지고 검색 결과도 비어 버린다.
DB_PATH = "./rag_agent/chroma_db"

# 저장해 둔 Chroma DB를 다시 불러온다. 임베딩을 새로 만들지 않으므로 API 비용이 들지 않는다.
# 저장할 때와 같은 임베딩 모델, 같은 collection_name을 써야 한다. (검색어도 같은 모델로 벡터로 바꿔야 비교가 된다)
vectorstore = Chroma(
    persist_directory=DB_PATH,
    embedding_function=OpenAIEmbeddings(model="text-embedding-3-small"),
    collection_name="korean_pdf",
)

# DB에 저장된 전체 데이터(ids, documents, metadatas 등)를 꺼내는 메서드. 반환값을 쓰지 않아서 실행 결과에는 영향이 없다.
# DB가 제대로 불러와졌는지 보려면 print(len(vectorstore.get()["ids"]))처럼 개수를 출력하면 된다. (510이 나와야 함)
vectorstore.get()

# 벡터 DB -> retriever: 질문과 가장 비슷한 청크 3개를 돌려주는 검색기
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# retriever -> 도구. 인자는 query(검색어) 하나이고, name과 description이 LLM에게 전달되는 도구 설명서가 된다.
retriever_tool = create_retriever_tool(
    retriever,
    name="pdf_search",
    # LLM은 이 설명을 보고 언제 이 도구를 쓸지 판단한다.
    description="use this tool to search information from the Korean Spelling Rules PDF document",
)

if __name__ == "__main__":
    # 도구를 직접 실행: 검색된 청크 3개의 본문이 빈 줄로 이어진 문자열 하나가 돌아온다. (쪽 번호 같은 메타데이터는 빠짐)
    response = retriever_tool.invoke("부엌이 들어간 경우 어떻게 발음하나요?")
    print(response)
```

## 1. 저장된 벡터 DB 불러오기

`Chroma(persist_directory=..., embedding_function=..., collection_name=...)`는 디스크에 저장된 DB를 그대로 불러온다. 임베딩을 다시 만들지 않으니 시간도 API 비용도 들지 않는다. 다만 **저장할 때와 같은 임베딩 모델(`text-embedding-3-small`)과 같은 `collection_name`(`korean_pdf`)**을 써야 한다. 검색어도 같은 모델로 벡터로 바꿔야 저장된 벡터와 비교할 수 있기 때문이다.

`vectorstore.get()`은 DB에 저장된 전체 데이터(`ids`, `documents`, `metadatas` 등)를 딕셔너리로 꺼내는 메서드다. 이 코드에서는 반환값을 쓰지 않아 결과에는 영향이 없다. DB가 제대로 불러와졌는지 확인하려면 `print(len(vectorstore.get()["ids"]))`처럼 개수(510)를 출력하면 된다.

**경로 주의:** `DB_PATH = "./rag_agent/chroma_db"`는 **실행한 위치 기준** 상대 경로다. `ex1008` 폴더에서 실행했기 때문에 `ex1008/rag_agent/chroma_db`를 찾았다. 경로가 틀리면 에러가 나지 않고 **그 위치에 빈 DB가 새로 만들어져서 검색 결과가 빈 문자열**이 된다. 같은 버전(langchain-chroma 1.1.0)으로 없는 경로를 지정해 확인해 보니, 에러 없이 빈 폴더가 생기고 도구 결과는 `''`였다. 검색 결과가 비어 있으면 경로부터 의심해야 한다.

## 2. retriever와 검색 도구

- `vectorstore.as_retriever(search_kwargs={"k": 3})`: 질문과 가장 비슷한 청크 3개를 돌려주는 검색기
- `create_retriever_tool(retriever, name, description)`: 검색기를 도구로 감싼다. 인자는 `query`(검색어) 하나이고, `name`과 `description`이 LLM에게 전달되는 도구 설명서가 된다. LLM은 이 설명을 보고 "맞춤법 PDF에서 찾아야 하는 질문"일 때 이 도구를 부른다.

결과는 청크 3개의 본문이 빈 줄로 이어진 **문자열 하나**다. 벡터 DB에서 각 청크의 쪽 번호를 찾아보니 다음과 같았다.

| 순위 | 쪽 | 내용 | 질문과의 관련성 |
|---|---|---|---|
| 1 | 240쪽 | 연음 규칙. `부엌이[부어키]`(○), `부엌이[부어기]`(×) | 질문의 답이 그대로 들어 있다 |
| 2 | 241쪽 | 받침 뒤에 모음으로 시작하는 말이 올 때의 발음 예 (`밭 아래[바다래]`, `겉옷[거돋]` 등) | 비슷한 주제(받침 + 모음) |
| 3 | 55쪽 | 어간 끝 'ㄷ'이 바뀌는 용언 (`걷다`, `묻다` 등) | 관련 없음 |

확인한 점:

- **1순위에 정답이 있다.** "부엌이는 [부어키]로 발음해야 한다"는 내용이라, 에이전트는 이 결과만으로 답할 수 있다.
- **관련 없는 결과도 들어온다.** `k=3`은 관련이 있든 없든 항상 가장 가까운 3개를 돌려준다. 3순위(55쪽)는 발음이 아니라 활용에 관한 내용이다. 이걸 걸러내고 답하는 건 LLM의 몫이다.
- **쪽 번호가 빠진다.** `create_retriever_tool`은 기본적으로 청크 **본문만** 빈 줄로 이어 붙여 돌려주고, `page_label` 같은 메타데이터는 넣지 않는다. 그래서 이대로면 에이전트가 "몇 쪽에 나온다"고 근거를 댈 수 없다. `document_prompt=PromptTemplate.from_template("[{page_label}쪽] {page_content}")`를 넘기면 청크 앞에 쪽 번호가 붙는다. 같은 버전으로 확인해 보니 `[3쪽] 내용 3\n\n[0쪽] 내용 0`처럼 나왔다.
- 첫 줄 `'한글 맞춤법', '표준어 규정' 해설` 뒤에는 6.5.2에서 본 깨진 문자(`\x13\x14\x19`)가 그대로 들어 있다. 터미널에는 보이지 않을 뿐이다.

## 정리

| 단계 | 코드 | 핵심 |
|---|---|---|
| DB 불러오기 | `Chroma(persist_directory=..., embedding_function=..., collection_name=...)` | 저장할 때와 같은 임베딩 모델·컬렉션 이름. 경로가 틀리면 에러 없이 빈 DB |
| 검색기 | `vectorstore.as_retriever(search_kwargs={"k": 3})` | 가장 비슷한 청크 3개 (관련 없어도 3개) |
| 검색 도구 | `create_retriever_tool(retriever, name, description)` | 인자는 `query` 하나. 결과는 본문만 이어 붙인 문자열 (메타데이터 없음) |
| 쪽 번호 포함 | `document_prompt=PromptTemplate.from_template(...)` | 근거 위치를 LLM에게 함께 전달 |
