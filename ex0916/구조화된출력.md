# with_structured_output()으로 구조화된 출력 받기

원래는 [teddynote 교재의 StructuredOutputParser 예제](https://github.com/teddylee777/langchain-kr/blob/main/03-OutputParser/03-StructuredOutputParser.ipynb)(`ResponseSchema` + `StructuredOutputParser`)를 따라 실습하려고 했는데, 이 방식은 현재 LangChain 공식 문서에서 `langchain_classic`(레거시) 패키지로 분류되어 있고, "구조화된 출력" 공식 가이드에서도 더 이상 권장하지 않는다. 그래서 같은 예제(질문에 답하면서 답변의 근거/출처도 함께 받기)를 최신 권장 방식인 **`with_structured_output()`**으로 다시 정리했다.

`output_parser.ipynb`에서도 `with_structured_output()`을 한 번 다뤘는데, 거기서는 이메일 본문에서 여러 필드를 뽑아내는 예제였다. 여기서는 원래 튜토리얼처럼 **질문에 답하면서 `answer`(답변)와 `source`(출처)를 함께 반환**하는, 좀 더 단순한 Q&A 형태의 예제로 연습했다.

## 1. 원하는 출력 구조를 Pydantic 모델로 정의

원래 튜토리얼의 `ResponseSchema`는 아래처럼 두 필드를 정의한다.

```python
response_schemas = [
    ResponseSchema(name="answer", description="사용자의 질문에 대한 답변"),
    ResponseSchema(name="source", description="사용자의 질문에 답하기 위해 사용된 `출처`, `웹사이트주소` 이여야 합니다."),
]
```

`with_structured_output()`을 쓸 때는 이 스키마를 `BaseModel`(Pydantic)로 정의한다. 필드 구성은 동일하게 `answer`, `source` 두 개로 맞췄다.

```python
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field


class AnswerWithSource(BaseModel):
    answer: str = Field(description="사용자의 질문에 대한 답변")
    source: str = Field(
        description="사용자의 질문에 답하기 위해 사용된 출처(웹사이트 주소 등)"
    )
```

## 2. LLM에 구조화된 출력 연결

```python
llm = ChatOpenAI(temperature=0)

# AnswerWithSource 스키마에 맞는 구조화된 객체를 바로 반환하는 모델.
llm_with_structure = llm.with_structured_output(AnswerWithSource)
```

`with_structured_output(AnswerWithSource)`를 호출하면, 모델이 함수 호출(도구 호출) 방식으로 `AnswerWithSource` 스키마에 맞는 객체를 바로 반환하도록 LangChain이 처리해준다. `StructuredOutputParser`처럼 포맷 지시문을 직접 프롬프트에 넣고 응답을 다시 파싱하는 과정이 필요 없다.

## 3. 질문에 답변 + 출처 함께 받기

```python
answer = llm_with_structure.invoke("대한민국의 수도는 어디인가요?")
print(answer)
print(answer.answer)  # 답변만 따로 꺼내기
print(answer.source)  # 출처만 따로 꺼내기
```

프롬프트 템플릿 없이 질문 문자열을 그대로 넘겨도 `answer`, `source` 필드를 가진 `AnswerWithSource` 객체가 바로 반환된다.

```python
answer2 = llm_with_structure.invoke("세종대왕의 업적은 무엇인가요?")
print(answer2)
```

## 정리: StructuredOutputParser(레거시) vs with_structured_output()

| | `StructuredOutputParser` (레거시) | `with_structured_output()` (권장) |
|---|---|---|
| 스키마 정의 | `ResponseSchema` 리스트 | Pydantic `BaseModel` (또는 TypedDict, JSON Schema) |
| 동작 원리 | 프롬프트에 포맷 지시문을 텍스트로 삽입 → 모델이 그 형식대로 텍스트 응답 → 파서가 다시 파싱 | 모델의 함수 호출(도구 호출) 기능을 이용해 모델이 곧바로 구조화된 결과를 생성 |
| 반환 타입 | `dict` | 정의한 Pydantic 모델 객체 (필드에 `.`으로 접근) |
| 프롬프트 작성 | `{format_instructions}`를 직접 프롬프트에 끼워 넣어야 함 | 별도 포맷 지시문 불필요 |
| 스트리밍 | 텍스트 chunk 단위로 자연스럽게 스트리밍 가능 | 함수 호출 결과가 완성되어야 파싱 가능해서, 텍스트처럼 매끄러운 토큰 스트리밍은 기대하기 어려움 |
| 현재 상태 | LangChain 문서상 `langchain_classic`(레거시)로 분류 | 공식 "구조화된 출력" 가이드가 권장하는 방식 |

결과적으로 두 방식 모두 "질문에 대한 답변과 출처를 함께 구조화해서 받는다"는 목적은 같지만, `with_structured_output()`이 코드가 더 간결하고 최신 LangChain에서 권장되는 방법이다.
